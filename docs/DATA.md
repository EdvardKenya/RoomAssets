# DATA — модель данных и формат JSON

## Сущности

### Room
| Поле      | Тип       | Описание                         |
|-----------|-----------|-----------------------------------|
| id        | string    | уникальный идентификатор          |
| name      | string    | название аудитории                |
| capacity  | number    | вместимость                       |
| features  | string[]  | признаки, напр. "projector"       |

### Asset
| Поле          | Тип    | Описание                                          |
|---------------|--------|-----------------------------------------------------|
| id            | string | уникальный идентификатор                            |
| name          | string | название                                            |
| inventoryCode | string | инвентарный номер                                   |
| status        | enum   | "available" \| "in_use" \| "maintenance"            |

### Booking
| Поле         | Тип    | Описание                                                        |
|--------------|--------|-------------------------------------------------------------------|
| id           | string | назначается сервером (crypto.randomUUID())                        |
| resourceType | enum   | "room" \| "asset"                                                 |
| resourceId   | string | id аудитории или единицы инвентаря                                |
| title        | string | название/повод брони                                              |
| start        | string | момент начала, UTC, ISO-8601/RFC 3339 (`2025-09-05T08:00:00.000Z`) |
| end          | string | момент окончания, UTC, ISO-8601/RFC 3339                          |
| notes        | string?| комментарий (опционально)                                          |

Время хранится в UTC и отображается в локальной таймзоне (конвертация —
`app/src/utils/datetime.ts`).

## REST API (бэкенд, `server/`)

| Метод  | Путь               | Описание                                        |
|--------|---------------------|---------------------------------------------------|
| GET    | /api/rooms          | список аудиторий                                  |
| GET    | /api/assets         | список инвентаря                                   |
| GET    | /api/bookings        | список броней                                      |
| POST   | /api/bookings        | создать бронь; 409 + `{conflicts}` при пересечении |
| PUT    | /api/bookings/:id     | изменить бронь; та же проверка пересечений         |
| DELETE | /api/bookings/:id     | удалить бронь                                      |
| GET    | /api/export           | весь AppData целиком (для кнопки «Экспорт»)        |
| POST   | /api/import           | заменить все данные (для кнопки «Импорт»)          |

## Формат файла экспорта/импорта

```json
{
  "rooms": [ { "id": "r-101", "name": "Аудитория 101", "capacity": 30, "features": ["projector", "whiteboard"] } ],
  "assets": [ { "id": "a-proj-1", "name": "Проектор Epson", "inventoryCode": "PRJ001", "status": "available" } ],
  "bookings": [
    {
      "id": "b-1",
      "resourceType": "room",
      "resourceId": "r-101",
      "title": "Семинар",
      "start": "2025-09-05T08:00:00Z",
      "end": "2025-09-05T09:30:00Z",
      "notes": "Нужен HDMI"
    }
  ]
}
```

Пример — `/seed/seed.example.json`, идентичен сид-данным бэкенда (`server/src/data.js`).

## Бизнес-ограничения

Недопустимы пересечения интервалов `Booking` для одного и того же ресурса.
Интервалы полуоткрытые `[start, end)` — брони «встык» не конфликтуют. Проверка
продублирована на фронтенде (`app/src/utils/overlap.ts`, для мгновенной обратной
связи в форме) и на бэкенде (`server/src/overlap.js`, как источник истины —
клиентская проверка не является защитой от гонок/обхода).
