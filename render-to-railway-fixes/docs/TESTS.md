# TESTS — ручные сценарии проверки

## Автотесты
`cd app && npm run test` — пересечения интервалов и конвертация времени.

## Ручные (локально)
1. `cd server && npm install && npm run dev` — бэкенд на :4000.
2. `cd app && npm install && npm run dev` — фронтенд на :5173, обращается к
   бэкенду по `VITE_API_URL` из `.env.development`.
3. Создать бронь без конфликта → появляется в списке.
4. Создать бронь с пересечением на том же ресурсе → форма показывает ошибку,
   бронь не создаётся (проверить также в `server/data/store.json`, что она не
   добавилась).
5. Брони «встык» (end одной = start другой) → не конфликт, обе сохраняются.
6. Редактирование без сдвига времени → не конфликтует само с собой.
7. Удаление → пропадает из списка и из `store.json`.
8. Фильтры: текст, дата, тип/конкретный ресурс.
9. Экспорт → Импорт того же файла → данные не меняются (роундтрип).
10. Импорт файла без нужных полей → понятная ошибка, данные не затираются.

## После деплоя
11. Открыть GH Pages URL, убедиться, что данные приходят с Railway (Network →
    запросы на `.../api/...` со статусом 200).
12. Проверить CORS: с другого origin (например, открыть DevTools Console на
    постороннем сайте и сделать `fetch` на твой Railway-адрес) запрос должен
    быть заблокирован.
